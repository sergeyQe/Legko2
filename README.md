# legko2: обёртка над потоками Keitaro

Тестовое задание «Adrobot». Сервис состоит из двух частей:

1. **Редактор кампании.** Показывает потоки Keitaro с офферами и их долями, позволяет добавлять и убирать офферы, закреплять вес, а изменения публикует в режиме «черновик → Push to KT»: пока вы не нажали **Отправить в KT**, в Keitaro ничего не меняется.
2. **Создатель кампаний.** По названию, коду страны и ID оффера создаёт в Keitaro кампанию с двумя потоками: поток 1 принимает посетителей из выбранной страны и редиректит на Google, поток 2 ведёт на оффер.

Стек: FastAPI, SQLAlchemy, Alembic, PostgreSQL (Docker), React + TypeScript (Vite).

> **Важно: Keitaro по умолчанию подменён заглушкой.** Ключа Keitaro у разработки нет, поэтому сервис по умолчанию работает в режиме `mock`: встроенная заглушка с данными из скриншотов задания. Реальный клиент Keitaro написан по схеме `openapi.json` и покрыт тестами на подставных ответах, но **на живом Keitaro не проверялся**. Подробности и список допущений в разделе «Ограничения».

## Что нужно установить

- Python 3.11 или новее
- Node.js 20 или новее (проверено на 24) и npm
- Docker (для PostgreSQL)

## Быстрый старт

Команды для Git Bash или Linux/macOS; в PowerShell вместо `cp` используйте `Copy-Item`.

```
# 1. Настройки (при необходимости поправьте значения)
cp .env.example .env

# 2. PostgreSQL в Docker
docker compose up -d db

# 3. Бэкенд: зависимости, миграции, запуск
cd backend
python -m pip install -e ".[dev]"
python -m alembic upgrade head
python -m uvicorn app.main:app --reload --port 8000
```

В другом терминале:

```
# 4. Фронтенд
cd frontend
npm install
npm run dev
```

Откройте http://localhost:5173. Документация API (Swagger): http://localhost:8000/docs.

Если бэкенд работает не на `http://localhost:8000`, задайте адрес фронтенду: `VITE_API_URL=http://host:port npm run dev`.

## Как показать сценарий (режим mock)

При `KEITARO_MODE=mock` сверху страницы появляется **демо-панель**. Она имитирует действия «со стороны» Keitaro. Если вы перезапускали бэкенд, нажмите «Сбросить»: заглушка Keitaro хранится в памяти и после перезапуска возвращается к исходным данным, а наши черновики лежат в PostgreSQL.

1. **Кампании → Открыть редактор** у `campaign 2`. Потоки загружаются из Keitaro: поток 1 без офферов показан пустым, у потока 2 три оффера 33/33/34.
2. **Добавление.** Введите `11112` в поле под офферами и нажмите «Добавить»: доли стали 25% ×4, поток жёлтый («Не опубликован»), в Keitaro ничего не изменилось.
3. **Обновите страницу** (F5): черновик остался. **Отменить изменения** возвращает поток к состоянию Keitaro.
4. **Добавьте оффер ещё раз → Отправить в KT.** Откроется предпросмотр: что добавится, как изменятся доли. Подтвердите: в Keitaro теперь четыре оффера по 25%.
5. **Убрать из потока:** оффер станет серым с 0%, у остальных 33/33/34. После отправки он исчезнет из Keitaro, но останется в обёртке как «удалён» с кнопкой «Вернуть в поток».
6. **Закрепить вес** (булавка): закреплённая доля не меняется при добавлении и удалении, остальные делят остаток.
7. **Объединение (merge).** Уберите оффер 11110 в черновике, нажмите в демо-панели «Правка: вес 11110 → 40%» и «Правка: оффер 11120 в KT», затем «Отправить в KT»: диалог покажет автоматически объединённое и попросит решить спорный пункт.
8. **Ошибка отправки.** «Сбой отправки в KT», затем «Отправить в KT»: на потоке появится плашка «Не отправлено» с кнопкой «Повторить», черновик цел.
9. **Создание кампании:** вкладка «Создать кампанию». Домен, группа и источник предзаполнены, любой можно оставить «Не выбрано». «Сбой создания потока 2» показывает отчёт «создана не полностью» и повтор.

## Режимы Keitaro

| Режим | Как включить | Что происходит |
|---|---|---|
| `mock` (по умолчанию) | `KEITARO_MODE=mock` | Встроенная заглушка, ключ не нужен. Работает демо-панель и маршруты `/mock/*` |
| `real` | `KEITARO_MODE=real`, `KEITARO_URL`, `KEITARO_API_KEY` | Запросы к Keitaro Admin API (`Api-Key`). Демо-маршрутов нет |

## Миграции

Схема БД управляется Alembic (папка `backend/alembic`). Команды выполняются в папке `backend`:

```
python -m alembic upgrade head                      # применить миграции
python -m alembic downgrade base                    # откатить всё
python -m alembic revision --autogenerate -m "..."  # создать миграцию по изменениям моделей
python -m alembic check                             # проверить, что модели и миграции совпадают
```

Адрес БД берётся из `DATABASE_URL`.

## API

Полное описание с примерами и кодами ошибок: Swagger на `/docs` (у каждого эндпоинта указано, меняет ли он Keitaro). Основные группы:

| Группа | Эндпоинты | Меняет Keitaro? |
|---|---|---|
| Кампании | `GET /campaigns`, `GET /campaigns/{id}`, `POST /campaigns/{id}/fetch` | нет |
| Офферы потока | `POST /streams/{id}/offers`, `DELETE /streams/{id}/offers/{offer_id}`, `POST .../restore`, `PUT .../pin`, `POST /streams/{id}/cancel` | нет, только черновик |
| Предпросмотр и Push | `POST /streams/{id}/preview`, `POST /streams/{id}/push` | Push да, полная замена офферов потока |
| Создание кампании | `POST /campaign-creator/campaigns`, `POST .../{id}/retry-stream2` | да, сразу |
| Справочники | `GET /references`, `GET /offers/search?q=` | нет |
| Служебные | `GET /health`, `GET /meta` | нет |
| Демо (только mock) | `POST /mock/external-change`, `POST /mock/failure`, `POST /mock/reset`, `GET /mock/state` | только заглушка |

Все ошибки приходят в одном формате `{"code": "...", "message": "...", "details": {...}}`; `message` готов для показа пользователю. Коды: `VALIDATION`, `WEIGHTS_INVALID`, `EMPTY_STREAM`, `NOT_FOUND`, `OFFER_STATE_ERROR`, `MERGE_CONFLICT`, `CREATE_PARTIAL`, `KEITARO_UNREACHABLE`, `KEITARO_AUTH`, `KEITARO_EDITION`, `KEITARO_NOT_FOUND`, `KEITARO_REJECTED`, `KEITARO_ERROR`, `DOMAIN_ERROR`, `INTERNAL_ERROR`.

## Как это работает

- **Две копии состояния.** По каждому офферу потока хранится снимок Keitaro (`in_kt`, `kt_weight`) и черновик (`active`, `weight`, `pinned`). Поток «не опубликован», пока они различаются.
- **Доли.** Активные офферы всегда дают 100%. Закреплённые доли не меняются, остаток делится поровну, лишний процент достаётся последнему свободному (33/33/34). Убранный оффер имеет 0%.
- **Push** полностью заменяет офферы потока итогом черновика; убранные офферы в Keitaro не отправляются и остаются у нас в архиве (`removed`). Поток без активных офферов отправить нельзя. При любой ошибке черновик не меняется.
- **Merge.** Перед отправкой черновик объединяется с текущим потоком Keitaro по трём версиям (снимок загрузки, черновик, Keitaro). Бесспорное объединяется само, спорное (например, оффер убран у нас, а в Keitaro у него изменили вес) требует решения пользователя. Лучше не менять поток в Keitaro между загрузкой и отправкой: на странице висит предупреждение.
- **Загрузка потоков** не сбрасывает черновик. Оффер, пропавший в Keitaro, остаётся в обёртке как удалённый с возможностью вернуть. Если в Keitaro доли не дают 100%, они пересчитываются и поток помечается неопубликованным.

## Тесты

```
# Бэкенд (в папке backend)
python -m pytest

npm run typecheck
npm run build
```

Сценарий из видео задания (загрузка, добавление, отмена, Push, удаление, архив, возврат, правка в Keitaro, пины) проверяется в `backend/tests/test_scenario_video.py` на SQLite. Чтобы прогнать его и на PostgreSQL, создайте пустую базу и задайте переменную:

```
docker exec legko2-db psql -U legko2 -c "CREATE DATABASE legko2_test"
TEST_DATABASE_URL=postgresql+psycopg://legko2:legko2@localhost:5432/legko2_test python -m pytest tests/test_scenario_video.py
```

Тест очищает таблицы этой базы, поэтому не указывайте в `TEST_DATABASE_URL` рабочую базу.

## Деплой на сервер (Docker + Caddy + sslip.io)

Боевой запуск: PostgreSQL, бэкенд и Caddy в `docker-compose.prod.yml`. Caddy отдаёт собранный фронтенд, проксирует `/api/*` на бэкенд и сам получает HTTPS-сертификат. Режим Keitaro на сервере `mock`, пароля на сайте нет (открытая демонстрация).

Нужно: сервер с Linux (Ubuntu или Debian), доступ по SSH, открытые из интернета порты **80 и 443** (в том числе в облачном файрволе провайдера). Домена покупать не нужно: адрес `<IP через дефисы>.sslip.io` указывает на ваш IP автоматически (для IP `203.0.113.10` это `203-0-113-10.sslip.io`).

Команды выполняются на сервере, каждая одной строкой:

```
curl -fsSL https://get.docker.com | sh
git clone https://github.com/sergeyQe/Legko2.git && cd Legko2
cp .env.prod.example .env.prod
sed -i "s/^POSTGRES_PASSWORD=.*/POSTGRES_PASSWORD=$(openssl rand -hex 16)/" .env.prod
sed -i "s/^SITE_ADDRESS=.*/SITE_ADDRESS=$(curl -s https://api.ipify.org | tr . -).sslip.io/" .env.prod
docker compose --env-file .env.prod -f docker-compose.prod.yml up -d --build
```

Первая сборка занимает несколько минут. Затем откройте `https://<IP через дефисы>.sslip.io` (сертификат выпускается около минуты после первого запуска). Swagger: `https://<адрес>/api/docs`.

Полезные команды:

```
docker compose --env-file .env.prod -f docker-compose.prod.yml ps
docker compose --env-file .env.prod -f docker-compose.prod.yml logs -f backend
git pull && docker compose --env-file .env.prod -f docker-compose.prod.yml up -d --build
docker compose --env-file .env.prod -f docker-compose.prod.yml exec db pg_dump -U legko2 legko2 > backup.sql
```

Примечания:

- **Если порты 80 и 443 на сервере заняты** (например, другим сайтом или VPN), запускайте на другом порту по HTTP, не трогая занятое. В `.env.prod` задайте `SITE_ADDRESS=:80`, `HTTP_PORT=8081`, `HTTPS_PORT=18443` (оба порта должны быть свободны: проверка `ss -ltn | grep -E ':(8081|18443) '`), разрешите порт 8081 в файрволе (`ufw allow 8081/tcp` и облачный файрвол) и запустите ту же команду `docker compose ... up -d --build`. Сайт откроется по `http://<IP>:8081` (или `http://<IP через дефисы>.sslip.io:8081`) без HTTPS: Let's Encrypt для сертификата нужны именно порты 80 и 443.
- Первая строка (установка Docker) нужна, только если Docker ещё не стоит. Файрвол на самом сервере: `sudo ufw allow 80,443/tcp` (если используется ufw).
- Миграции применяются автоматически при старте бэкенда. Данные PostgreSQL хранятся в томе `pgdata_prod` и переживают пересборку.
- Заглушка Keitaro хранится в памяти бэкенда: после перезапуска контейнера нажмите «Сбросить» в демо-панели.
- Сайт открыт всем: любой посетитель может пользоваться демо и нажимать «Сбросить». Это допустимо для режима `mock`; перед включением реального Keitaro (`KEITARO_MODE=real`) обязательно закройте сайт паролем (в Caddyfile директива `basicauth`).
- У sslip.io общий лимит выпуска сертификатов Let's Encrypt; если сертификат не выпускается, подождите или временно укажите `SITE_ADDRESS=http://<адрес>.sslip.io` (без HTTPS).


## Ограничения и допущения

Реальный клиент Keitaro (`backend/app/keitaro/http_client.py`) написан по `openapi.json` и **не проверялся на живом Keitaro**. В коде такие места помечены «Не подтверждено»:

- `PUT /streams/{id}` с массивом `offers` заменяет офферы целиком (а не дополняет).
- Ключ действия «редирект» (`http`) и имя фильтра страны (`country`) при создании потока 1; поле `action_type` для потока с офферами.
- Название оффера в потоке берётся запросом `GET /offers/{id}`; поиск по базе делается на нашей стороне по `GET /offers`.
- Ссылка «Кампания в Keitaro» ведёт на `/admin/` указанного Keitaro, а не на конкретную кампанию (формат ссылки в админке не подтверждён).

Прочее:

- Нет пользователей и авторизации: сервис рассчитан на доверенную сеть.
- Один инстанс Keitaro. Колонки «Статистика» и «Тренды» пока заглушки.
- Заглушка Keitaro хранится в памяти: после перезапуска бэкенда используйте «Сбросить» в демо-панели.
- Интерфейс проверен автоматическими тестами и сборкой, но визуальный вид и контрастность цветов стоит посмотреть глазами.
- При ошибке Keitaro сразу после успешной записи в Keitaro, но до записи в нашу БД состояния могут разойтись; следующая загрузка потоков их выравнивает.
- В консоли Windows русские буквы в логах отображаются корректно в UTF-8 (`chcp 65001`); при другой кодировке нечитаемые символы заменяются, работа не нарушается.
